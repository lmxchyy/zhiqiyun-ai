# 小程序登录与手机验证码登录联调报告

更新时间：2026-07-16

## 当前实际登录体系

当前项目已有统一认证体系，并非重新创建用户体系。

- 小程序登录页：`apps/user-uni/src/pages/WechatLoginPage.vue`
- 小程序认证 API：`apps/user-uni/src/features/auth/api.ts`
- 小程序统一请求 Client：`apps/user-uni/src/api/client.ts`
- 共享认证服务：`packages/shared-auth/src/index.ts`
- 后端认证路由：`backend-go/internal/httpserver/server.go`
- 后端登录实现：`backend-go/internal/httpserver/auth_api.go`
- 后端短信与手机号身份实现：`backend-go/internal/httpserver/auth_flow_api.go`

当前支持：

- 微信手机号一键登录：`POST /api/v1/auth/wechat/phone-login`
- 手机短信验证码登录：`POST /api/v1/auth/sms/send`、`POST /api/v1/auth/sms/login`
- 密码登录：`POST /api/v1/auth/login`
- 后端保留微信 code-only 登录：`POST /api/v1/auth/wechat-mini-program/login`
- Refresh Token：`POST /api/v1/auth/refresh`
- 退出登录：`POST /api/v1/auth/logout`
- 账号安全状态：`GET /api/v1/auth/security`

## 本次修复内容

### 1. 短信验证码状态接入现有 Session Store

修复前，短信验证码挑战和发送限流仅保存在 `authFlowCoordinator` 的进程内存中。多 API 实例或生产 Redis session 场景下，用户可能在一个实例发送验证码，另一个实例登录验证失败。

修复后：

- 复用现有 `authSessionStore` 扩展 `smsChallengeStore`
- 本地开发使用 `localAuthSessions`
- 生产接入 Redis 时使用 `redisAuthSessions`
- 验证码挑战、尝试次数、发送限流均通过同一 session store 保存
- 未新增用户表、JWT 模块或独立登录体系

### 2. 账号冲突错误码更明确

手机号用户和微信用户已经分别存在且属于不同 `user_id` 时，不自动合并。

当前返回：

- HTTP 409
- `AUTH_ACCOUNT_MERGE_REQUIRED`
- 提示：手机号与微信身份已关联不同账号，需要人工确认后合并

### 3. 小程序 401 自动刷新

修复前，小程序 API Client 收到 401 会直接清除本地会话并跳转登录页，即使本地仍有 refresh token。

修复后：

- 标准 API Client 收到 401 会先调用 `/api/v1/auth/refresh`
- 刷新成功后自动重试原请求一次
- 刷新失败或重试后仍 401，才清除登录态并跳转登录页
- `fetch`、上传、下载封装也补充了一次刷新重试

### 4. 账号与安全补充绑定能力

新增登录后手机号绑定接口：

- `POST /api/v1/auth/mobile/bind`

处理规则：

- 复用现有短信验证码发送与校验能力
- 只绑定当前已登录用户
- 如果手机号已属于其他用户，返回 `AUTH_MOBILE_ALREADY_BOUND`
- 不创建新用户、不创建新钱包、不改变已有作品和订单归属

小程序“我的 - 设置 - 账号与安全”已补充：

- 手机号脱敏展示
- 微信绑定状态展示
- 发送验证码
- 绑定或修改手机号
- 绑定微信小程序身份
- 设置或修改密码
- 退出当前账号

### 5. 后台用户管理身份展示

后台客户/用户管理列表补充派生展示字段：

- 手机号脱敏
- 登录方式
- 微信绑定状态
- OpenID/UnionID 脱敏

本次展示手机号、微信状态，并补充后台“强制退出全部设备”操作。

### 6. 退出全部设备与后台强制退出

新增接口：
- `POST /api/v1/auth/logout-all`
- `POST /api/v1/admin/customers/:id/logout-all`

实现说明：
- 本地 session store 支持按 `user_id` 删除 access token、refresh token 和微信会话缓存。
- Redis session store 增加 `auth:user-sessions:{user_id}` 索引，新登录的 access token 和 refresh token 都会写入索引；同时扫描旧的 `auth:session:*` 作为上线前历史登录态兜底。
- 用户在小程序“我的 - 设置 - 账号与安全”可退出全部设备。
- 后台“客户/用户管理”列表可对指定用户执行强制退出全部设备，操作前有二次确认。
- 操作只失效登录态，不修改用户资料、钱包、会员、作品、订单或企业关系。

### 7. 后台身份查看、解绑与冻结登录

新增后台接口：

- `GET /api/v1/admin/customers/:id/identities`
- `POST /api/v1/admin/customers/:id/identities/mobile/unlink`
- `POST /api/v1/admin/customers/:id/identities/wechat-mini-program/unlink`
- `POST /api/v1/admin/customers/:id/freeze-login`
- `POST /api/v1/admin/customers/:id/unfreeze-login`

实现说明：

- 后台“客户/用户管理”列表补充“身份、解绑手机、解绑微信、冻结/启用”操作。
- 身份详情只展示脱敏手机号、OpenID、UnionID、登录方式、注册来源和最近登录信息，不输出完整敏感身份。
- 解绑手机号或微信前会检查是否还保留至少一种可用登录身份，禁止解绑最后一种登录方式。
- 解绑手机、解绑微信和冻结登录成功后会强制退出该用户全部设备，避免旧 token 继续使用。
- 冻结/启用只修改用户登录状态，不修改钱包、会员、作品、订单或企业关系。
- PostgreSQL 存储会写入管理员审计日志，记录操作类型、原因和变更项。

### 8. 账号冲突合并工单

新增接口：

- `GET /api/v1/admin/customers/:id/account-merge-requests`
- `GET /api/v1/admin/account-merge-requests`
- `POST /api/v1/admin/account-merge-requests/:id/status`
- `GET /api/v1/admin/account-merge-requests/:id/preview`
- `POST /api/v1/admin/account-merge-requests/:id/execute`

处理规则：

- 微信手机号登录命中“手机号用户”和“微信用户”两个不同 `user_id` 时，不自动合并。
- 后端返回 HTTP 409、`AUTH_ACCOUNT_MERGE_REQUIRED`，并生成或复用一条待处理合并工单。
- 小程序登录页会提示“账号需要人工合并”和工单号，便于客服定位。
- 后台“客户/用户管理”行操作增加“合并工单”，只展示脱敏手机号、OpenID、UnionID 和处理状态。
- 后台“客户/用户管理”行操作增加“执行合并”，需要二次确认并显式传入 `confirm: true`。
- 工单状态支持 `PENDING`、`IN_REVIEW`、`RESOLVED`、`CANCELLED`、`REJECTED`。
- 执行合并会迁移核心个人资产归属：点数账户、Token 记录、订单、生成任务、作品、计费流水、模型路由和微信身份。
- 被合并来源账号会清除手机号/微信身份并标记为 `MERGED`，同时强制退出来源账号全部设备。
- 如果两个账号都存在代理身份或运营中心身份，后端会阻断自动执行，要求人工专项处理。

## 数据库变更

本次新增运行时投影表：

- `xz_auth_account_merge_requests`

用途：

- 记录微信手机号登录冲突产生的人工合并申请。
- 支持按主账号、冲突账号和状态查询。
- 保存真实标识用于后台处理，前端和后台展示均只输出脱敏信息。

当前身份仍基于现有结构：

- `xz_users.mobile`
- `xz_users.wechat_union_id`
- `xz_users.raw.wechatOpenIds`
- `xz_point_accounts` 作为点数账户

如后续要完整支持多 provider、多 app、解绑历史明细和身份级唯一约束，建议第二阶段新增 `auth_accounts` 统一身份表。

## 2026-07-16 追加：账号合并执行覆盖面增强

本轮继续补齐 `POST /api/v1/admin/account-merge-requests/:id/execute` 的真实合并覆盖范围：

- JSON projection 合并新增覆盖：PPT 演示文稿 `presentations.userId`、旧版 AI 员工 `agents.ownerId`、智能体调用 `agentCalls.userId`、GEO 品牌/任务 `geoBrands.ownerId`、`geoTasks.ownerId`。
- PostgreSQL 合并新增覆盖：`xz_ai_state` 会合并收藏任务、隐藏任务、收藏夹和智能体会话，并删除来源账号 AI 状态。
- AI 状态合并会处理会话 ID 冲突；如果来源账号当前会话被改名，`activeConversationId` 会同步指向改名后的会话。
- PostgreSQL 合并新增覆盖：知识库个人归属字段，包括 `xz_knowledge_bases.owner_user_id`、`xz_knowledge_documents.owner_user_id`、`xz_knowledge_document_versions.created_by`、`xz_ai_agents.owner_user_id`、`xz_ai_agent_conversations.user_id`。
- PostgreSQL 合并新增覆盖：企业/RBAC 基础身份，包括 `xz_tenants.owner_user_id`、`xz_tenant_members.user_id`、`xz_user_roles.user_id`、`xz_user_role_context.user_id`。
- 企业成员冲突处理：如果目标账号已经是同一租户成员，不覆盖目标成员记录，来源账号成员记录会置为 `DISABLED/MERGED` 并在执行结果里返回 `tenantMemberConflictsDisabled` 警告。
- 合并执行成功后会同时强制退出来源账号和目标账号全部设备，确保重新登录后刷新手机号、微信身份、企业角色和资产归属。
- 后台「执行合并」完成后会弹出迁移明细，把 `moved` 中的技术字段翻译为点数账户、订单、PPT、知识库、企业成员等中文项，并展示后端返回的人工关注警告。
- 后台「执行合并」前会先调用预检接口，展示预计迁移明细、警告和阻断原因；如果预检返回 `executable=false`，不会进入真正执行。
- 预检和执行对生产数据库差异做了兼容：知识库、企业/RBAC 等扩展表或扩展列不存在时会跳过对应统计/迁移并返回警告，不会因为可选投影表缺失直接失败。
- 双方都存在代理身份或运营中心身份时，预检阶段会返回 `executable=false` 和阻断原因，后台不会继续执行合并。

仍然不自动粗暴合并的高风险资产：

- 双方同时存在代理身份或运营中心身份时继续阻断自动合并。
- 双方在同一企业中已有复杂角色差异时，只做冲突安全迁移/禁用来源成员，不直接覆盖目标账号角色策略。
- 代理钱包、运营中心复杂分润链路、企业钱包和人工结算类资产仍建议走人工专项核对。
