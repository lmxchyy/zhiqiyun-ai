# 知启云AI企业级AI创作与智能体平台 V1.0 源程序说明文档

## 1. 文档目的

本文档说明用于软件著作权登记的源程序组成、技术架构、目录结构、数据库设计和 API 设计。内容来自当前仓库扫描，不改变任何源代码。

## 2. 技术架构

### 2.1 用户端

- 技术：Vue 3.5、TypeScript 5.8、uni-app、Vite 5、Pinia。
- 目标终端：Android/iOS App、H5、微信小程序，并保留 Harmony 构建入口。
- 请求边界：页面通过 `apps/user-uni/src/api/client.ts`、领域 API 与共享业务 SDK 访问服务端。
- 平台适配：终端差异通过 uni-app 条件编译和共享平台适配包处理。
- 本地状态：认证令牌、刷新令牌、用户上下文和部分草稿写入终端本地存储。

### 2.2 管理端

- 技术：Vue 3.5、TypeScript 5.8、Vite 7、Pinia、Axios、Element Plus。
- 模块：客户与企业、商品与计费、AI 能力、知识库、素材、渠道增长和系统管理。
- 请求边界：统一由 `admin-vue/src/api/client.ts` 和各领域 API 模块访问后端。

### 2.3 服务端

- 技术：Go 1.25、Gin 1.10、`database/sql`、pgx、go-redis。
- 形态：模块化单体 HTTP 服务，按认证、生成、PPT、知识库、企业、支付、文件、Connector 和后台管理拆分。
- 基础设施：PostgreSQL 为生产数据源；Redis 用于认证会话、缓存、Connector 队列和分布式锁；S3 兼容存储或本地存储保存文件与媒体。
- 接口：`backend-go/internal/httpserver/server.go` 统一注册路由、中间件和模块实例。

## 4. 前端结构说明

用户端 `pages.json` 当前扫描到 103 个页面路径。页面层负责显示和用户交互，领域层负责请求参数、平台差异和状态转换，共享 API Client 负责认证头、租户头、请求标识、刷新令牌和统一错误处理。核心页面包括登录、首页、创作中心、生图、视频、PPT、智能体、知识库、作品、钱包和企业中心。

管理端以 `adminNavigation.ts` 组织六个一级域：管理总览、客户与企业、商品与计费、AI 与内容、渠道与增长、系统管理。Pinia 保存登录与后台状态，Axios 拦截器统一处理鉴权、请求和响应。

## 5. 后端结构说明

`cmd/api/main.go` 加载配置并创建基础设施客户端；`internal/infra/clients.go` 根据环境变量连接 PostgreSQL 和 Redis；`internal/httpserver/server.go` 创建模块、注册中间件和路由。当前路由文件扫描到约 494 个 GET/POST/PUT/PATCH/DELETE 注册点。

核心应用服务包括：

1. `internal/app/generation`：统一生成任务服务与执行状态。
2. `internal/app/ppt`：PPT 大纲、页面、视觉计划、编辑和导出。
3. `internal/app/knowledge`：知识摄取、检索、RAG 运行、引用和智能体。
4. `internal/app/payment`：支付状态机、回调、权益发放和幂等。
5. `internal/app/commission`：佣金计算、快照和结算规则。
6. `internal/httpserver/enterprise_*`：租户、组织、成员、角色、认证、额度和审计。

## 6. 数据库设计

### 6.1 实际数据库

当前代码通过 `github.com/jackc/pgx/v5/stdlib` 连接 PostgreSQL，SQL 中使用 `JSONB`、`TIMESTAMPTZ`、`ON CONFLICT` 等 PostgreSQL 语法。Redis 不替代主数据库，主要保存短期会话、缓存和协调状态。

### 6.2 主要业务域

| 业务域 | 代表数据 |
|---|---|
| 用户与认证 | 用户、登录身份、会话、刷新令牌、协议接受记录 |
| 企业与权限 | 租户、组织、成员、角色、认证、服务状态、审计日志 |
| AI 生成 | 模型、能力、参数 Schema、生成任务、内容审核、AI 标识 |
| 知识库 | 知识库、文档、分块、向量、智能体、对话、运行与引用 |
| 作品与文件 | 资产、项目、上传会话、对象存储配置、回收站 |
| 商业化 | 商品、价格、订单、支付记录、钱包、Token、权益、退款、发票 |
| 渠道与结算 | 代理关系、佣金规则、佣金记录、结算申请和账本 |
| 企业 Connector | Connector、用户绑定、外部消息、任务和授权会话 |

### 6.3 数据一致性

- 金额和权益由服务端商品与价格配置决定。
- 支付回调、查单补偿和人工补发复用统一权益发放服务。
- 生成任务与支付操作使用业务幂等键，避免重复生成、扣费或发放。
- 账务变更保留流水和规则快照，历史记录不因后续配置修改而改变。
- 企业读写携带租户与组织上下文，仓储查询按范围过滤。

## 7. API 设计

### 7.1 通用约定

- 基础路径：`/api/v1`。
- 数据格式：JSON；文件采用上传初始化、完成确认或受控上传接口。
- 鉴权：Bearer 访问令牌与刷新令牌；部分公开目录允许匿名访问。
- 上下文头：`X-Tenant-Id`、`X-Organization-Id`、`X-Client-Platform`、`X-Client-Version` 和 `X-Request-Id`。
- 错误处理：使用 HTTP 状态码与业务错误信息，客户端集中转换为用户提示。

### 7.2 代表接口

| 领域 | 代表接口 |
|---|---|
| 认证 | `/auth/login`、`/auth/sms/login`、`/auth/refresh`、`/auth/logout` |
| 生成 | `/generation-tasks`、`/generation-tasks/:id/retry` |
| PPT | `/ppt/generate`、`/ppt/outline/generate`、`/presentations/:id`、`/ppt/export/pptx` |
| 作品 | `/assets`、`/assets/:id`、`/assets/:id/download` |
| 知识库 | `/knowledge-bases`、`/knowledge-search`、`/knowledge-conversations/:id/runs` |
| 企业 | `/enterprise/overview`、`/enterprise/members`、`/enterprise/organizations/tree` |
| 支付 | `/payment/products`、`/payment/orders`、`/payment/orders/:orderNo/status` |
| 管理端 | `/admin/enterprises`、`/admin/ai/models`、`/admin/api/provider-channels` |

## 8. AI 能力调用流程

客户端参数校验 → 认证与权限校验 → 服务端读取模型与计费配置 → 生成任务幂等检查 → 预留额度 → 调用模型提供方 → 保存结果与作品 → 内容审核与 AI 标识 → 确认扣费或失败释放 → 客户端轮询/刷新结果。

## 9. 安全设计

- 密码使用不可逆散列保存，访问令牌与会话具备有效期。
- 上游模型、支付、Connector 和对象存储密钥通过环境变量或加密配置注入。
- 文件上传检查大小、类型和访问权限，私有文件通过临时访问地址下载。
- 高风险管理操作保留操作者、原因、时间和资源标识。
- 企业密钥与个人敏感标识不在日志和前端响应中输出明文。
