# 知启云 AI｜AI 灵感模块需求与开发约束

> 用于 `feature/ai-inspiration` 分支 / 独立 worktree 开发\
> 本文档作为 Codex 实施 AI 灵感功能时的需求与工程约束基准。

## 1. 项目目标

在知启云 AI 中新增一级功能模块 **「AI 灵感」**。

核心定位不是向用户展示模型，而是展示
**"用户可以完成什么任务"**。用户从应用场景和模板出发，通过上传素材或输入需求，一键复用现有
AI 创作能力完成生成。

## 2. 产品定位与典型场景

AI 灵感本质上是：

**模板市场 + 创作入口**

模板本身只负责预设：

-   Prompt / Prompt 模板
-   推荐模型或能力路由
-   生成参数
-   示例图 / 示例结果
-   使用说明

典型应用场景包括：

-   电商：商品主图、商品场景图、电商海报、产品包装
-   新媒体：小红书封面、抖音/短视频封面、公众号配图
-   品牌与企业：Logo、品牌视觉、企业宣传海报、招商物料
-   人像：AI 证件照、商务写真、职业形象照
-   教育与创意：儿童绘本、IP 形象、创意插画
-   空间设计：家居/装修效果图
-   后续扩展：AI 视频模板、AI PPT 模板、AI 文案模板、AI 智能体模板

## 3. 用户核心流程

``` text
打开 AI 灵感
    ↓
浏览 / 搜索模板
    ↓
点击模板
    ↓
上传素材 / 输入需求
    ↓
自动加载 Prompt、推荐能力和参数
    ↓
调用知启云 AI 现有生成能力
    ↓
生成作品
    ↓
进入现有作品中心
```

原则：**AI 灵感不新增一套生成流程，只作为现有创作能力的模板化入口。**

## 4. 用户端页面需求

AI 灵感首页至少包含：

-   搜索框
-   Banner
-   分类导航
-   推荐模板
-   热门模板
-   最新模板
-   我的收藏
-   最近使用

模板详情页至少包含：

-   模板名称
-   模板介绍
-   示例图 / 示例结果
-   使用说明
-   上传图片或其他素材
-   输入用户需求
-   风格选择
-   比例选择
-   尺寸选择
-   AI 优化
-   立即生成

点击「立即生成」后，必须复用现有生成接口和生成流程。

生成完成后的作品继续进入现有 **作品中心**。

## 5. 模板分类

首期至少考虑：

1.  电商营销
2.  企业办公
3.  新媒体运营
4.  品牌设计
5.  人像写真
6.  儿童教育
7.  家居装修
8.  AI 创意

架构上必须预留：

-   AI 图片
-   AI 视频
-   AI PPT
-   AI 文案
-   AI 智能体

不要把 Template Schema 写死成只支持图片。

## 6. Template Schema 要求

模板数据结构至少考虑：

-   模板 ID
-   模板名称
-   模板类型
-   分类
-   封面图
-   描述
-   Prompt / Prompt Template
-   推荐模型或能力路由
-   风格
-   比例
-   尺寸
-   其他生成参数
-   标签
-   示例图 / 示例结果
-   使用量
-   收藏量
-   排序权重
-   推荐状态
-   热门状态
-   模板状态
-   创建时间
-   更新时间

状态至少考虑：

-   草稿
-   已上架
-   已下架

Schema 必须具备后续扩展能力。

-   热门模板配置
-   排序管理
-   上架 / 下架
-   使用统计

后续可扩展：

-   Banner / 运营位管理
-   模板审核

-   AI 生图接口
-   视频生成能力
-   PPT 生成能力
-   模型管理
-   模型路由

-   现有数据库规范

## 9. 禁止事项（强约束）

### 9.1 产品与架构

禁止：

-   重新开发一套 AI 生图链路
-   为 AI 灵感重新开发独立视频生成链路
-   新建独立计费体系
-   新建独立作品存储体系
-   无必要修改已有生成核心流程
-   为 AI 灵感进行大规模全局重构

AI 灵感只负责：

> 模板发现 + 模板配置 + 参数预设 + 调用现有创作能力。

### 9.2 Git

禁止：

-   未经确认切换到 `main` / `master` 开发
-   `git reset --hard`
-   擅自覆盖已有修改
-   擅自 stash 其他人的工作
-   删除其他功能代码
-   修改其他 worktree
-   未经确认直接 push
-   未经确认直接 merge

## 11. Migration 并发约束

AI 灵感可能需要新增：

-   模板表
-   分类表
-   标签相关结构
-   收藏关系
-   最近使用 / 使用历史

但是 **第一阶段不得直接创建 Migration**。

必须先：

1.  判断是否真的需要新增数据库表
2.  判断需要几张表
3.  说明每张表存在的必要性
4.  检查项目当前最新 Migration 编号
5.  检查其他并行功能是否已经占用下一个编号
6.  用户确认后再分配 Migration 编号

目的：避免多个 Codex / worktree 并行开发时出现 Migration 编号冲突。

## 14. UI / UX 原则

整体风格要求：

-   现代
-   简洁
-   低学习成本
-   视觉优先
-   模板结果优先
-   不让普通用户理解底层模型

可以借鉴现代 AI 创作和模板产品的交互思路，但不得照搬。

核心体验：

> 用户不需要知道该选哪个模型，只需要知道自己想做什么。

例如用户看到：

-   商品主图
-   商务写真
-   招商海报
-   小红书封面
-   儿童绘本

而不是先看到一堆模型名称。

## 15. 最终验收原则

AI 灵感完成后必须满足：

-   用户可以从「我要做什么」出发完成创作
-   模板能够自动带入 Prompt
-   模板能够自动带入推荐能力和参数
-   图片生成仍走现有生成链路
-   Token / 积分仍走现有计费链路
-   作品仍进入现有作品中心
-   不重复建设已有能力
-   不破坏现有 AI 生图、视频、PPT 等功能
-   图片模板首期可用
-   架构能够扩展到视频、PPT、文案、智能体
-   管理后台可以维护模板
-   代码符合当前项目已有风格
-   具备必要单元测试、集成测试和回归验证
