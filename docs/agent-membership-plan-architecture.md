# 代理商会员套餐架构体系

## 目标定位

代理商会员套餐体系不是单纯的“会员价目表”，而是先知 AI 的渠道销售、客户权益、用量计费、订单收款和分润结算的统一商业骨架。

体系需要同时回答 5 个问题：

- 代理商卖什么：会员订阅、点数包、企业套餐、代运营服务、API 套餐。
- 卖给谁：个人客户、企业客户、渠道下级代理、代理商自用账号。
- 客户得到什么：点数、并发、模型权限、API 额度、Agent/GEO/代运营权益。
- 代理商赚什么：按订单、产品、套餐、层级和客户归属计算佣金。
- 平台如何控风险：订单、权益、佣金、退款、结算和审计都保留快照。

## 核心原则

1. 会员套餐面向客户，代理商等级面向渠道。
2. 套餐权益决定客户能用什么，代理商等级决定能卖什么和赚多少。
3. 订单支付成功后才发放权益、点数和佣金。
4. 订单必须保存套餐权益快照和分润规则快照，避免后续改价影响历史。
5. 退款要反向撤回权益、点数和未结算佣金。
6. 点数包、订阅套餐和人工服务要同属于“可售商品”，但计费规则不同。

## 角色分层

| 角色 | 业务定位 | 能力边界 |
| --- | --- | --- |
| 平台管理员 | 制定产品、套餐、价格、返佣和结算规则 | 全局管理 |
| 渠道经理 | 管理代理商、审核渠道、处理结算 | 渠道和财务协同 |
| 一级代理商 | 发展客户和下级代理，获得团队分润 | 可查看直客、团队业绩、佣金 |
| 二级代理商 | 发展客户，获得直客分润 | 可查看自己的客户和佣金 |
| 企业客户 | 购买企业套餐，管理成员额度 | 企业成员、配额和用量 |
| 普通会员 | 使用 AI 创作、API、Agent、GEO 等能力 | 按套餐权益使用 |

后续如果要支持更复杂渠道，可以把 `channel_agents.level` 从 1/2 扩展为 1/2/3，但第一版建议保持两级，降低合规和结算复杂度。

## 商品与套餐分层

### 商品类型

| 商品类型 | 示例 | 计费方式 | 是否参与返佣 |
| --- | --- | --- | --- |
| 会员订阅 | Basic、Pro、Ultimate、企业版 | 周期订阅 | 是 |
| 点数包 | 19.9 元、99 元、299 元、999 元点数包 | 一次性充值 | 是 |
| API 套餐 | API 月包、企业 API 包 | 固定费 + 用量 | 是 |
| Agent 套餐 | Agent 对话量、知识库容量 | 固定额度 + 超额 | 是 |
| GEO 套餐 | 品牌监测、报告次数 | 项目/月度 | 是 |
| 代运营服务 | 登录托管、内容发布、项目交付 | 人工服务订单 | 可配置 |

### 会员套餐结构

当前代码中的 `canonicalSubscriptionPlans()` 已有基础订阅层级，可以按商业语义整理为：

| 套餐 | 面向对象 | 价格 | 核心权益 |
| --- | --- | --- | --- |
| 体验版 | 新用户体验 | 免费 | 7 天、少量点数、低并发、基础模型 |
| Basic | 个人、小商家 | 29 元/月 | 基础点数、基础模型、普通并发 |
| Pro | 创作者、电商运营 | 139 元/月 | 更多点数、高质量模型、更高并发 |
| Ultimate | 工作室、代运营团队 | 699 元/月 | 大额度点数、团队高并发、优先能力 |
| 企业版 | 企业客户、重点代理 | 定制 | 自定义额度、成员管理、API/GEO/Agent 权益 |

### 点数包结构

点数包是补充消费能力，不替代会员等级。

| 点数包 | 价格 | 点数 | 业务定位 |
| --- | --- | --- | --- |
| 小额包 | 19.9 元 | 2500 点 | 低门槛补充 |
| 标准包 | 99 元 | 15000 点 | 普通高频用户 |
| 商业包 | 299 元 | 50000 点 | 商业创作 |
| 企业包 | 999 元 | 200000 点 | 团队或企业消耗 |

点数包可以参与代理商返佣，但不改变客户会员身份、并发、模型权限和服务等级。

## 代理商等级体系

代理商等级不应该直接等于会员套餐。建议拆成两张概念表：

- `channel_agents`：谁是代理商、上级是谁、状态是什么。
- `agent_level_policies` 或配置项：该等级能卖什么、返佣多少、是否允许发展下级。

### 推荐等级

| 等级 | 名称 | 目标对象 | 核心能力 |
| --- | --- | --- | --- |
| L0 | 普通用户 | 普通 AI 工具客户 | 购买会员、充值点数、使用 AI 工具 |
| L1 | 推广员 | 个人推广、社群主、达人 | 邀请客户、查看推广订单、获得轻量返佣 |
| L2 | 初级代理商 | 小团队、个人渠道 | 代理后台、客户管理、订单管理、佣金结算 |
| L3 | 高级代理商 | 企服老板、培训机构、代运营老板 | 企业客户报备、专属客服、发展 L1 推广员 |
| L4 | 城市合伙人 | 城市/区域渠道运营商 | 区域保护、区域代理管理、区域业绩返点 |
| L5 | 联合运营商 | 大渠道、战略合作方 | 独立 SaaS、独立价格策略、专属额度池、合同政策 |

其中 L5 就是原来简写的 KA/战略代理场景。后续统一使用 L0-L5，不再单独使用 KA 作为等级编码。

### 等级能力矩阵

| 能力 | L0 | L1 | L2 | L3 | L4 | L5 |
| --- | --- | --- | --- | --- | --- | --- |
| 购买会员和点数 | 支持 | 支持 | 支持 | 支持 | 支持 | 合同定义 |
| 推广返佣 | 不支持 | 支持 | 支持 | 支持 | 支持 | 合同定义 |
| 代理后台 | 不支持 | 轻量版 | 标准版 | 高级版 | 区域版 | 独立/定制 |
| 客户管理 | 不支持 | 仅推广客户 | 自有客户 | 自有客户 + L1 客户汇总 | 区域客户 | 合同范围 |
| 邀请下级代理 | 不支持 | 不支持 | 需平台审核 | 可发展 L1 | 可管理区域代理 | 合同定义 |
| 售卖会员订阅 | 不支持 | 支持 | 支持 | 支持 | 支持 | 合同定义 |
| 售卖点数包 | 不支持 | 支持 | 支持 | 支持 | 支持 | 合同定义 |
| 企业项目 | 不支持 | 线索推荐 | 线索报备 | 报价申请 | 可报价 | 合同定义 |
| 独立品牌/域名 | 不支持 | 不支持 | 不支持 | 可申请 | 支持 | 支持 |
| 结算周期 | 无 | 满额提现 | 月结或满额提现 | 月结 | 月结 + 区域返点 | 合同定义 |

## 返佣规则体系

返佣规则建议按“订单类型 + 产品类型 + 关系深度 + 代理等级”配置，而不是写死百分比。

### 规则维度

| 维度 | 示例 |
| --- | --- |
| 订单类型 | 订阅购买、续费、点数充值、企业定制、代运营 |
| 商品类型 | 会员、点数包、API、Agent、GEO、服务 |
| 收益人角色 | L1、L2、L3、L4、L5 |
| 关系深度 | 直推客户、下级代理客户 |
| 计算方式 | 固定金额、百分比、阶梯比例 |
| 释放策略 | 支付即释放、冷静期后释放、服务验收后释放 |
| 上限控制 | 单笔上限、总返佣比例上限 |

### 推荐默认比例

| 场景 | 直推代理 | 上级代理 | 说明 |
| --- | --- | --- | --- |
| 会员订阅首购 | 20% | 5% | 支持两级分润 |
| 会员续费 | 10% | 3% | 续费降低比例 |
| 点数充值 | 15% | 0-3% | 控制毛利 |
| 企业定制 | 10% 或人工 | 0-5% | 需合同审批 |
| 代运营服务 | 5-15% | 0-3% | 按毛利或回款配置 |

实际执行时，以后台 `commission_rules` 为准，并在 `commissions.rule_snapshot` 中保存快照。

## 客户归属规则

客户归属是分润的根，必须可审计。

### 归属来源

- 邀请码注册：`users.referred_by` 或客户档案 `agent_id`。
- 后台手动绑定：管理员把客户分配给代理商。
- 兑换码绑定：代理商创建的兑换码被客户使用。
- 订单补录：线下成交时由财务/渠道经理指定代理商。

### 归属优先级

1. 订单创建时显式指定代理商。
2. 客户档案中的当前归属代理商。
3. 用户注册推荐人。
4. 兑换码所属代理商。
5. 无归属，不生成渠道佣金。

订单生成佣金时，应把当时的归属关系写入订单或佣金快照，后续客户转移不影响历史订单。

## 权益发放流程

```text
客户下单
-> 选择会员套餐/点数包/服务商品
-> 创建订单，保存价格快照和权益快照
-> 支付成功或人工标记收款
-> 发放会员权益/点数/服务额度
-> 根据客户归属和返佣规则生成佣金
-> 佣金进入待释放或待结算状态
-> 冷静期/退款期后释放
-> 代理商申请提现
-> 平台审核并生成结算单
-> 打款完成
```

退款流程必须反向处理：

```text
订单退款
-> 撤回未消耗权益或按策略扣减
-> 撤回未结算佣金
-> 已结算佣金生成负向调整
-> 写入审计日志
```

## 后台模块设计

### 套餐中心

管理“卖给客户的套餐”：

- 会员订阅套餐。
- 点数包。
- API/GEO/Agent/代运营套餐。
- 权益配置：点数、并发、模型权限、API 额度、GEO 任务数、Agent 对话数。
- 可售状态、展示价格、推荐标识、排序。

### 代理商中心

管理“谁来卖”：

- 一级/二级代理商列表。
- 渠道树。
- 审核、启用、冻结。
- 邀请码。
- 客户归属。
- 代理等级能力。

### 分润中心

管理“赚多少、何时结”：

- 返佣规则。
- 佣金明细。
- 冷静期/释放状态。
- 提现申请。
- 结算单。
- 负向调整。

### 订单中心

管理“交易事实”：

- 客户订单。
- 订单类型。
- 价格快照。
- 权益快照。
- 支付状态。
- 退款和补差价。
- 关联代理商和佣金。

### 用量中心

管理“客户实际用了多少”：

- 点数流水。
- API 用量。
- 图片生成任务。
- Agent 对话。
- GEO 任务。
- 企业成员额度。

## 第一阶段落地范围

第一阶段不要一次性做复杂账单系统，先把“套餐 + 代理 + 分润 + 订单”跑通。

- 套餐中心展示订阅套餐和点数包。
- 代理商中心支持 L1/L2 渠道树和启停。
- 订单支付成功后发放会员点数或充值点数。
- 根据客户归属生成佣金。
- 退款撤回未结算佣金。
- 分润中心能查看佣金、提现、结算单。
- 后台能配置返佣规则，至少支持订阅和点数充值两类订单。

## 验收标准

- 管理员能看到所有会员套餐、点数包和可售状态。
- 管理员能创建或启停一级/二级代理商。
- 客户通过代理归属购买会员后，客户权益到账。
- 佣金按规则生成，并能追溯订单、客户、代理商和规则快照。
- 点数充值订单能生成点数流水和代理佣金。
- 退款订单能撤回套餐权益和未结算佣金。
- 代理商只能看到自己的客户、订单、业绩和佣金。
- 平台管理员能查看全局收入、渠道贡献、佣金成本和结算状态。

## 推荐实施顺序

1. 固化套餐目录：订阅套餐、点数包、企业定制套餐。
2. 固化代理等级：L1/L2 能力、状态和渠道树。
3. 固化客户归属：邀请码、后台绑定、订单归属快照。
4. 固化订单结算：支付成功发权益、发点数、生成佣金。
5. 固化退款反结算：撤权益、撤佣金、审计日志。
6. 增强后台页面：套餐中心、代理商中心、分润中心联动。
7. 接入计费中心：订阅、账单、用量、发票和支付催收。

## 结论

建议把“代理商会员套餐架构体系”定义为四层：

```text
商品套餐层 -> 客户权益层 -> 渠道归属层 -> 分润结算层
```

其中，商品套餐层负责卖什么，客户权益层负责能用什么，渠道归属层负责是谁带来的，分润结算层负责赚多少和怎么结。这样既能承接当前 Basic/Pro/Ultimate/企业版会员，也能继续扩展点数包、API 套餐、Agent/GEO 套餐和代运营服务。
