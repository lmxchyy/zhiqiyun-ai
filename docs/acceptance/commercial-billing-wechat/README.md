# 知启云 AI 计费中心与微信虚拟支付验收记录

## 实施范围

保留计费中心 V1 的 6 个页面：计费总览、模型计费规则、供应商成本、计费事件、任务对账、钱包流水。

新增商业计费的 8 个页面：客户计费、套餐产品、订阅管理、优惠券、发票、贷项红冲、付款请求、支付催收。页面数据均来自 PostgreSQL 或现有微信虚拟支付商品配置，不包含演示种子或 Mock 接口。

## 微信虚拟支付边界

- 商品价格和基础权益只由服务端商品配置决定，小程序只提交 `productCode`、数量和可选的 `couponCode`。
- 优惠券只支持赠送 credits、赠送图片额度或延长会员天数，不改变微信虚拟支付的固定商品金额。
- 下单事务同时写入支付订单、支付记录、发票、付款请求和优惠券占用记录。
- 微信回调、官方查单补偿和后台人工补发继续共用 `GrantOrderEntitlements`，权益发放带事务、独立账本和幂等保护。

## 成功任务完整链路

1. 后台维护虚拟商品映射和服务端价格，管理员配置并启用权益型优惠券。
2. 小程序读取服务端商品及适用优惠券，创建订单时不上传价格或权益数值。
3. 服务端按商品配置计算金额并保存不可变快照；同一事务创建付款请求、待支付发票，并将优惠券置为 `RESERVED`。
4. 微信虚拟支付回调或官方查单补偿验证签名、用户、商品和快照金额。
5. `GrantOrderEntitlements` 幂等发放基础权益；同一事务发放优惠券附加权益并写入权益账本。
6. 优惠券变为 `APPLIED`，发票变为 `PAID`，付款请求变为 `SUCCEEDED`，会员商品同步生成或更新 `ACTIVE` 订阅。
7. 后台可从客户计费、订阅、发票、付款请求、支付催收和既有钱包流水页面追踪完整链路。

## 失败任务完整链路

1. 下单后、支付确认前失败或关闭：订单关闭，付款请求变为 `CANCELLED`，优惠券占用变为 `CANCELLED`，不发放任何权益。
2. 微信已支付但权益事务失败：保留已支付事实并标记权益处理失败；官方查单或人工补发再次进入同一个幂等服务，避免重复发放。
3. 退款：微信退款记录驱动发票/付款请求状态，并生成贷项红冲记录；当前仍要求人工核对并处理已发权益回收，防止自动误扣用户权益。

## 当前遗留问题

1. 生产环境仍需配置真实的微信虚拟支付 Offer、商品 ID、证书和回调密钥，并在上线前完成微信沙箱/正式环境联调。
2. 发票页面当前提供交易发票台账与人工开票状态，不包含自动电子发票服务商对接。
3. 支付催收当前记录催收事件和结果，不自动发送短信、邮件或服务通知。
4. 贷项红冲审批不直接触发微信退款；实际退款与已发权益回收仍需人工复核。
5. 优惠券按微信虚拟支付合规边界只增加权益，不提供现金折扣或改价。
