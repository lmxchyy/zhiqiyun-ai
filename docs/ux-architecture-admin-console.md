# 先知云 AI 管理后台 UX Architecture Specification

状态：P0–P4 已实施并通过运行态验收  
更新时间：2026-07-18  
适用范围：`admin-vue` 管理员控制台，以及企业集成中心的只读汇总接口；不改变代理商端、用户端、小程序、Connector 配置写入流程或数据结构。

## 1. 目标与边界

### 目标用户

| 角色 | 主要关注点 | 高频任务 |
| --- | --- | --- |
| 平台管理员 | 全局运行状态、权限、安全 | 查看总览、配置系统、管理账号与菜单 |
| 客户/企业运营 | 客户生命周期、企业服务 | 查客户、审企业、看套餐与风险 |
| 商业化/财务 | 商品、订单、计费、对账 | 配套餐、处理支付、核对成本与账务 |
| AI 运营 | 模型能力、渠道、限额、调用质量 | 配能力、切渠道、查日志与限额 |
| 内容运营 | 素材、页面、知识库 | 管素材、装修页面、维护知识库 |
| 渠道运营 | 渠道、邀新、分佣、结算 | 看渠道、管理伙伴、处理佣金与结算 |

### 核心任务

1. 在 2 次导航动作内进入目标业务域。
2. 在同一业务上下文内切换关联子页面，不反复返回侧栏。
3. 保留原模块 ID、接口、权限和页面状态，降低迁移风险。
4. 把“按技术模块堆叠”调整为“按业务任务组织”。
5. 让新增模块有唯一归属和可自动校验的导航注册方式。

### 不在本阶段处理

- 不合并后端服务、数据库表、API 路由或计费账本。
- 不更改企业 Connector 的租户解析、密钥存储和幂等链。
- 不改变用户端、代理商端及小程序导航。
- 不删除旧模块；先收敛入口，再依据使用数据决定下线。

## 2. 信息架构

### 导航模型

采用三级模型：`业务域 -> 侧栏入口 -> 页内子导航`。

- 业务域：稳定的一级心智模型，控制在 5–7 个。
- 侧栏入口：面向任务的聚合入口，标题使用业务语言。
- 页内子导航：承载原有细分模块，模块 ID 与数据能力保持不变。
- 顶部已打开页签：表示工作会话，不承担信息架构分类。

### 已实施结构

| 一级业务域 | 侧栏入口 | 页内模块 |
| --- | --- | --- |
| 管理总览 | 管理总览 | 分析页、工作台、仪表盘 |
| 客户与企业 | 客户中心、企业中心、归属关系 | 客户、企业列表/认证/详情域、客户归属 |
| 商品与计费 | 商品与权益、订单与支付、定价与成本、账务与对账、营销优惠 | 产品目录、套餐权益、支付商品、订阅实例、订单、支付、发票、成本、账务、优惠券等 |
| AI 与内容 | AI 能力配置、接入与调用治理、知识库、素材库、页面运营 | 模型、参数、渠道、限额、日志、API 设置、知识、素材、页面配置 |
| 渠道与增长 | 渠道总览、伙伴与运营中心、邀新与升级、分佣与结算 | 渠道、运营中心、等级、邀请、升级、佣金、钱包与结算单 |
| 系统管理 | 系统设置、组织与后台账号、权限与菜单、存储资源 | 系统、后台账号、部门、菜单、对象存储 |

共 6 个一级业务域、22 个侧栏入口，覆盖 72 个管理员模块。用户端、代理商端、运营中心端保持各自导航。

### 合并判定规则

模块满足以下至少两项时，可收敛为同一侧栏入口：

- 面向同一业务对象，例如商品、订单、企业或渠道。
- 由同一角色在连续任务中使用。
- 共享筛选条件、详情上下文或操作结果。
- 页面之间是配置、记录、对账等上下游关系。

以下情况不做数据或页面级强合并：

- 权限边界不同。
- 风险等级不同，例如查看与资金发放。
- 生命周期不同，例如配置项与不可变审计记录。
- 需要独立 URL、刷新恢复或深链分享。

## 3. CSS / Layout 系统

### 页面骨架

```text
┌──────────┬──────────────────────────────────────────────┐
│ Brand    │ Header / Search / Account                    │
│          ├──────────────────────────────────────────────┤
│ Domain   │ Open work tabs                               │
│ sidebar  ├──────────────────────────────────────────────┤
│          │ Section tabs                                 │
│          ├──────────────────────────────────────────────┤
│          │ Page content                                 │
└──────────┴──────────────────────────────────────────────┘
```

### 布局约束

- 侧栏负责业务域与聚合入口；页内子导航负责关联模块切换。
- 页内子导航使用横向滚动，不允许压缩到不可点击宽度。
- 900px 以下页内导航改为纵向标题 + 横向滚动页签。
- 页面内容继续沿用既有容器宽度和 Element Plus 密度设置。
- 侧栏折叠后通过悬浮面板呈现同一组入口，不复制另一套数据。

### 视觉令牌

新组件只消费现有全局变量，不声明新的品牌色：

| 用途 | Token |
| --- | --- |
| 面板背景 | `--admin-panel` |
| 边框 | `--admin-border` |
| 主文本 | `--admin-text` |
| 次文本 | `--admin-muted` |
| 主色 | `--color-primary` |
| 主色浅背景 | `--color-primary-light` |
| 聚焦/悬停边框 | `--color-border-active` |

间距使用 6/10/12/14/18px 小步进；圆角 8/10px；触控高度不低于 34px。后续若统一设计令牌，应由全局主题替换，不在局部组件硬编码品牌值。

## 4. 组件边界

| 层 | 职责 | 不负责 |
| --- | --- | --- |
| `adminNavigation.ts` | 声明业务域、聚合入口、模块归属、页签集合 | 权限请求、页面数据、业务动作 |
| `moduleRegistry.ts` | 统一解析模块 ID、canonical URL、旧地址别名、企业动态路径和权限键 | 页面呈现、数据请求 |
| `App.vue` Shell | 选择当前入口、权限过滤、打开页签、渲染活动模块 | 重复声明模块分组 |
| `AdminSectionTabs.vue` | 展示与键盘操作页内子导航，发出模块选择事件 | 修改 Store、调用 API、判断权限 |
| `stores/admin.ts` | 保存模块目录、活动模块和模块数据加载 | 决定信息架构标题与归组 |
| 业务页面组件 | 展示数据、执行领域动作 | 改写全局导航结构 |

新增管理员模块时必须完成两项注册：

1. 在模块目录中声明模块 ID、标题与数据能力。
2. 在导航注册表中指定唯一业务域和侧栏入口。

静态校验必须阻止未知模块、重复归属、遗漏归属、无效主入口和越界用户端模块进入管理员导航。

## 5. 交互模型

### 侧栏选择

1. 点击聚合入口，打开其主模块。
2. 进入该入口的子模块后，侧栏仍高亮聚合入口。
3. 权限不足时整个受限入口不出现，不显示不可用占位项。
4. 折叠侧栏的悬浮菜单与展开态使用同一活动状态。

### 页内子导航

- 仅在同一入口含 2 个及以上可直接切换模块时显示。
- 点击后复用现有 `selectAdminModule` 流程，保留刷新、搜索和打开页签行为。
- 使用 `role=tablist/tab` 和 `aria-selected`。
- 支持 Left/Right 循环移动焦点，Home/End 跳到首尾。
- 企业详情等已有独立局部导航的深层页面不重复显示第二套页签。

### 工作页签

- 工作页签记录最近打开的具体模块，允许跨业务域并行处理。
- 默认只打开“分析页”，减少首次进入的视觉噪音。
- 关闭聚合入口下的某个工作页签不影响侧栏的信息架构。

### 状态与反馈

- 导航切换不触发写操作。
- 数据加载、空态、错误和重试继续由业务页面负责。
- 高风险操作继续遵循“预览 -> 警告/阻断 -> 确认 -> 执行”。
- 资金、权益、Connector 密钥和租户解析不因导航合并改变安全边界。

## 6. 实施计划

### P0：导航收敛（已完成）

- 建立单一导航注册表。
- 11 个旧分组收敛为 6 个业务域。
- 58 个可见细入口收敛为 22 个任务入口。
- 保留原模块 ID、组件、API 和权限判断。

### P1：上下文导航（已完成）

- 加入通用页内子导航。
- 对齐展开/折叠侧栏活动态。
- 将默认管理员工作页签降为 1 个。
- 加入静态与真实页面运行态校验。

### P2：模块壳拆分（已完成）

- 已拆出管理总览、商品计费、AI 治理、渠道增长四个领域呈现组件。
- `App.vue` 保留 Shell、组合状态和兼容入口，领域组件不直接散写请求。
- API Client 与 Store 合约保持兼容，生产构建与运行态均已验证。

### P3：企业集成中心（已完成）

- 将 Connector 状态纳入企业详情的“集成中心”，作为平台管理员只读摘要。
- 飞书、钉钉、企业微信、微信开放平台统一声明 `PlatformConnector` 适配器边界。
- 接口只返回配置状态、运行状态和密钥是否已加密配置；不返回 App ID、Connector Key、密文、错误原文或外部消息内容。
- 原 `/app/enterprise/connectors` 与 `/app/enterprise/feishu` 配置入口继续兼容，不改变企业侧配置写入流程。

### P4：路由、权限与运行态回归（已完成）

- 72 个模块均具有唯一 canonical URL；保留 `/admin`、`/admin/billing`、`/app/image-generation` 等旧地址。
- 浏览器前进/后退可恢复模块、页内标签和侧栏父入口高亮。
- 搜索按“模块名 > 区块名 > 一级业务域”排序，并过滤无权模块。
- 企业详情页签按权限过滤，缺少企业 ID 时不从缓存误恢复企业子页面。

### P5：任务工作台与跨域检索（已完成）

- 客户列表升级为“客户 360°”：在同一抽屉聚合身份、套餐权益、积分钱包、订单、计费事件、生成任务和账号合并记录。
- 订单列表升级为“订单履约时间轴”：按订单创建、支付确认、权益发放、分佣结算、履约完成展示状态与异常。
- 总览新增按角色过滤的快捷工作台、待办中心和异常中心，待办可直达对应业务模块。
- 统一后台列表的搜索、状态筛选、加载、空态、工具栏和行操作边界，渠道增长、客户、订单与通用模块复用同一列表组件。
- 全局搜索支持 `Ctrl/Cmd + K`，联合检索有权限的模块、当前页面记录、客户与订单；客户和订单响应只返回白名单摘要字段。
- 商品与套餐术语统一为“产品目录 / 套餐权益 / 支付商品 / 订阅实例”，平台治理统一为“系统管理”。
- 客户 360°、订单履约、全局命令面板和搜索状态均已从 `App.vue` 拆出为独立组件或 composable。

### P6：运营效率与数据驱动精简（已完成）

- 全局业务搜索从客户、订单扩展到企业、生成任务、支付流水和发票，共六类白名单摘要数据。
- 统一列表增加用户级保存视图、列显示配置、勾选批量操作和当前筛选结果 CSV 导出；配置按模块隔离保存在浏览器本地。
- 异常中心升级为服务端处置工单，包含负责人、OPEN/IN_PROGRESS/RESOLVED/CLOSED 状态、SLA 截止时间、关闭原因与不可覆盖的处理历史。
- 新增后台体验事件：模块访问、搜索结果跳转、任务开始/完成、批量操作和列表导出；搜索事件不保存搜索原文。
- 分析页新增 30 天体验数据、搜索跳转、任务完成率和低频入口观察名单；自动化浏览器事件通过 `synthetic` 标记排除，只有达到 100 个真人事件且覆盖 7 个活跃日才生成低频候选，不直接下线入口。
- 管理领域组件改为按需异步加载，主入口 JS 从约 666KB 降到约 426KB；构建不再出现大于 500KB 的业务主包警告。PPT 的约 345KB JS 与 185KB CSS 已退出首屏预加载，改为进入 PPT 功能时加载；体积预算脚本同时守住主入口和首屏依赖边界。
- 后台品牌 Logo 从约 494KB PNG 转为约 33KB WebP，页面品牌图与 favicon 统一使用轻量资源，原 PNG 仅保留为设计源文件。

### 后续：数据驱动精简（需运行数据）

- 采集入口访问量、任务完成率、返回侧栏次数和搜索后跳转率。
- 体验分析必须分别展示真人事件与自动化事件，测试脚本不得贡献样本成熟度或低频排序。
- 连续低使用且无合规要求的模块进入下线评审。
- 对高频跨页任务评估共享筛选器、批量动作或主从详情布局。

## 8. 成功指标

上线后建议用 2–4 周观察：

- 目标模块导航中位点击数不高于 2。
- 全局搜索后立即返回侧栏的比例下降。
- 同一业务入口内跨子模块任务完成率提升。
- 新增模块导航遗漏在 CI 阶段被 100% 拦截。
- 权限导致的空入口或错误入口为 0。
