# 代理商结构详细说明

## 结构总览

先知 AI 的代理商体系应拆成 6 个结构层：

```text
身份等级结构
-> 上下级渠道结构
-> 客户归属结构
-> 商品销售结构
-> 佣金结算结构
-> 后台权限结构
```

这 6 层不要混在一张表里。一个代理商账号既有身份等级，也有上级归属、客户资产、可售商品、佣金规则和后台权限。每一层变化的频率不同，必须分开管理。

## 一、身份等级结构

当前代码已经定义了 L0 到 L5 的代理等级策略，建议按下面结构理解。

| 等级 | 角色 | 身份定位 | 适合对象 | 开通方式 |
| --- | --- | --- | --- | --- |
| L0 | 普通用户 | 消费用户 | 普通使用 AI 工具的客户 | 注册账号 |
| L1 | 推广员 | 轻量分销 | 个人推广、社群主、达人 | 注册申请或邀请开通 |
| L2 | 初级代理商 | 正式代理 | 小团队、个人渠道 | 审核 + 代理套餐或业绩达标 |
| L3 | 高级代理商 | 区域/行业代理 | 企服老板、培训机构、代运营老板 | 销售额达标或人工签约 |
| L4 | 城市合伙人 | 城市/区域运营商 | 城市渠道、区域服务商 | 合同签约 + 业绩承诺 |
| L5 | 联合运营商 | 大渠道/战略合作 | 大渠道、战略合作方 | 商务签约 |

### L0 普通用户

普通用户不是代理商，只能购买会员、使用 AI 工具、充值 AI 点数。

限制：

- 不能获得推广返佣。
- 没有代理后台。
- 没有客户管理和佣金结算能力。

### L1 推广员

L1 是最低门槛的轻量分销角色，适合个人推广。

核心能力：

- 拥有专属邀请码和邀请链接。
- 推广用户购买会员或点数包后获得返佣。
- 可以查看自己的推广订单和佣金。

限制：

- 不可设置自己的销售价格。
- 不可开下级代理。
- 不建议开放复杂客户管理能力。

推荐返佣：

- 会员套餐：10%-20%。
- 点数充值：5%-10%。
- 企业项目：按单谈。

### L2 初级代理商

L2 是正式代理商，适合小团队和个人渠道。

核心能力：

- 进入代理后台。
- 管理自己的客户。
- 查看客户订单、用量和佣金。
- 销售会员套餐。
- 销售点数包。
- 报备企业版线索。
- 发起提现申请。

限制：

- 默认不能开二级代理。
- 如果要推荐下级代理，应进入平台审核，不应自动生效。
- 不建议开放独立定价和独立品牌。

推荐返佣：

- 会员套餐：20%-30%。
- 点数充值：10%-15%。
- 企业项目：10%-20%。

开通和保级：

- 开通：累计销售 1000 元或缴纳 999 年费。
- 保级：月销售不少于 1000 元。

### L3 高级代理商

L3 是区域或行业代理，面向更强的渠道伙伴。

核心能力：

- 享受更高返佣。
- 企业客户报备。
- 专属客服支持。
- 申请独立品牌页。
- 申请行业解决方案报价。
- 可发展 L1 推广员。

限制：

- 只能发展轻量推广员，不应无限发展多级代理。
- 企业项目价格和交付仍需平台审核。

推荐返佣：

- 会员套餐：30%-40%。
- 点数充值：15%-25%。
- 企业项目：20%-30%。

开通和保级：

- 开通：累计销售 1 万元或缴纳 2999 年费。
- 保级：月销售不少于 5000 元。

### L4 城市合伙人

L4 是城市或区域运营商，属于强运营角色。

核心能力：

- 城市区域保护。
- 独立代理站点。
- 自定义品牌名称和 logo。
- 管理区域代理。
- 企业客户报价。
- 区域业绩返点。
- 培训和销售物料。

限制：

- 不轻易开放。
- 必须人工审核。
- 必须绑定合同、区域、业绩承诺和退出机制。

推荐收益：

- 会员套餐：约 40%。
- 点数充值：20%-30%。
- 企业项目：约 30%。
- 区域团队返点：5%-10%。

开通和保级：

- 开通：月销售不少于 5 万元或合同签约。
- 保级：季度销售不少于 10 万元。

### L5 联合运营商

L5 是最高级别，属于战略合作，不适合普通后台自动开通。

核心能力：

- 独立 SaaS 站点。
- 独立支付账户，或平台代收后分账。
- 独立客户体系。
- 独立价格策略。
- 专属模型额度池。
- 专属企业服务政策。
- 定制功能。

限制：

- 必须商务签约。
- 必须单独合同、单独政策、单独风控。
- 佣金规则不应走普通比例规则，而应走合同策略。

## 二、上下级渠道结构

上下级结构解决“谁管理谁、谁看谁的数据、团队业绩怎么汇总”的问题。

核心表是 `channel_agents`：

| 字段 | 说明 |
| --- | --- |
| `id` | 代理商渠道身份 ID |
| `user_id` | 代理商对应的用户账号 |
| `parent_id` | 上级代理商 |
| `level` | 代理等级 |
| `status` | 状态 |
| `invite_code` | 邀请码 |
| `created_at` | 创建时间 |

### 推荐层级关系

```text
平台
├─ L5 联合运营商
│  └─ L4 城市合伙人
│     └─ L3 高级代理商
│        └─ L1 推广员
├─ L4 城市合伙人
│  └─ L3 高级代理商
│     └─ L1 推广员
├─ L3 高级代理商
│  └─ L1 推广员
├─ L2 初级代理商
└─ L1 推广员
```

第一阶段建议不要完全开放这棵树。更稳的策略是：

- L1 不允许发展下级。
- L2 不允许自动发展下级，只能推荐给平台审核。
- L3 可发展 L1 推广员。
- L4 可管理区域代理。
- L5 按合同定义组织结构。

### 为什么不能无限多级

无限多级会带来 4 个问题：

- 佣金链路过长，毛利被吃掉。
- 客户归属争议变多。
- 合规风险变高。
- 后台权限和数据隔离复杂度急剧上升。

因此建议平台只支持有限层级，佣金最多计算两层：直推收益和上级团队收益。

## 三、客户归属结构

客户归属解决“这个客户是谁带来的、谁可以看、谁能获得返佣”的问题。

### 归属来源

| 来源 | 说明 | 推荐优先级 |
| --- | --- | --- |
| 订单显式指定 | 后台创建订单时指定代理商 | 最高 |
| 客户档案绑定 | 管理员把客户绑定给代理商 | 高 |
| 邀请码注册 | 用户通过代理邀请码注册 | 中 |
| 兑换码使用 | 用户使用代理商兑换码 | 中 |
| 人工补录 | 线下成交后财务补录 | 视操作场景 |

### 归属规则

1. 客户同一时间只能有一个主归属代理商。
2. 订单生成时必须保存当时的归属快照。
3. 后续客户转移不影响历史订单佣金。
4. 客户转移必须有操作人、原因和审计日志。
5. 企业客户要区分“企业归属”和“企业成员个人归属”。

### 可见数据范围

| 角色 | 可见客户 |
| --- | --- |
| L1 | 自己邀请的客户 |
| L2 | 自己归属客户 |
| L3 | 自己客户 + 直属 L1 的客户汇总 |
| L4 | 区域内客户和团队汇总 |
| L5 | 合同约定范围内客户 |
| 平台管理员 | 全部客户 |

代理端接口已经有独立边界，例如：

```text
GET /api/v1/channel/me
GET /api/v1/channel/customers
GET /api/v1/channel/orders
GET /api/v1/channel/usage
GET /api/v1/channel/commissions
GET /api/v1/channel/withdrawals
POST /api/v1/channel/withdrawals
```

这些接口应始终只返回当前代理商有权查看的数据。

## 四、商品销售结构

代理商不是直接“卖权限”，而是销售平台定义好的商品。

### 可售商品

| 商品 | L1 | L2 | L3 | L4 | L5 |
| --- | --- | --- | --- | --- | --- |
| 会员套餐 | 可售 | 可售 | 可售 | 可售 | 合同定义 |
| 点数包 | 可售 | 可售 | 可售 | 可售 | 合同定义 |
| 企业版线索 | 可推荐 | 可报备 | 可报价申请 | 可报价 | 合同定义 |
| API 套餐 | 不建议 | 可推荐 | 可销售 | 可销售 | 可定制 |
| Agent/GEO 套餐 | 不建议 | 可推荐 | 可销售 | 可销售 | 可定制 |
| 代运营服务 | 不建议 | 可推荐 | 可销售 | 可销售 | 可定制 |
| 独立站点 | 不支持 | 不支持 | 可申请 | 支持 | 支持 |

### 价格权

价格权建议分三级：

| 类型 | 说明 | 适用等级 |
| --- | --- | --- |
| 平台统一价 | 使用平台公开价格销售 | L1/L2 |
| 折扣申请价 | 代理提交折扣申请，平台审核 | L3/L4 |
| 合同定制价 | 按合同独立定价 | L5 |

不要让普通代理商直接改商品价格，否则会造成价格体系混乱、客户投诉和佣金争议。

## 五、佣金结算结构

佣金结构解决“赚多少、什么时候可提现、退款怎么办”的问题。

核心表：

- `commissions`：佣金明细。
- `withdrawal_requests`：提现申请。
- `settlement_statements`：结算单。
- `xz_marketing_commission_rules`：营销返佣规则。

### 佣金状态

建议统一为：

```text
PENDING -> APPROVED -> SETTLED
        -> REJECTED
        -> REVERSED
```

含义：

- `PENDING`：订单刚支付，佣金待确认。
- `APPROVED`：已过冷静期或人工审核通过，可进入提现额度。
- `SETTLED`：已结算打款。
- `REJECTED`：审核拒绝。
- `REVERSED`：订单退款或风控撤回。

### 默认返佣规则

| 订单类型 | L1 | L2 | L3 | L4 | L5 |
| --- | --- | --- | --- | --- | --- |
| 会员套餐 | 15%，上限 20% | 25%，上限 30% | 35%，上限 40% | 40% | 合同 |
| 点数充值 | 8%，上限 10% | 12%，上限 15% | 20%，上限 25% | 25%，上限 30% | 合同 |
| 企业项目 | 按单谈 | 15%，上限 20% | 25%，上限 30% | 30% | 合同 |
| 团队业绩 | 不支持 | 不支持 | 可配置 | 5%-10% | 合同 |

### 结算周期

| 等级 | 推荐结算周期 |
| --- | --- |
| L1 | 满额后手动提现，平台审核 |
| L2 | 月结或满额提现 |
| L3 | 月结 |
| L4 | 月结 + 区域返点 |
| L5 | 合同约定 |

### 退款反向处理

退款时必须处理 3 件事：

1. 客户权益撤回或按已消耗比例扣减。
2. 未结算佣金直接撤回。
3. 已结算佣金生成负向调整，抵扣下期结算。

## 六、后台权限结构

代理商结构需要两个后台视角。

### 平台管理员视角

平台管理员在 `/admin` 里管理全局：

- 代理商列表。
- 代理商等级。
- 渠道树。
- 客户归属。
- 邀请记录。
- 返佣规则。
- 钱包和提现。
- 结算单。
- 风控和审计。

相关接口：

```text
GET    /api/v1/admin/channel-agents
POST   /api/v1/admin/channel-agents
GET    /api/v1/admin/channel-agents/tree
PATCH  /api/v1/admin/channel-agents/:id
GET    /api/v1/admin/marketing/agent-levels
GET    /api/v1/admin/marketing/commission-rules
PATCH  /api/v1/admin/marketing/commission-rules/:id
GET    /api/v1/admin/marketing/upgrade-plans
GET    /api/v1/admin/marketing/wallets
GET    /api/v1/admin/marketing/settlement-statements
GET    /api/v1/admin/commissions
POST   /api/v1/admin/commissions/:id/approve
POST   /api/v1/admin/commissions/:id/reject
```

### 代理商视角

代理商在 `/agent` 或代理后台里只管理自己的业务：

- 我的推广链接。
- 我的客户。
- 我的订单。
- 我的用量。
- 我的佣金。
- 我的提现。
- 我的下级或团队，按等级开放。

代理商不能看到平台全局客户，也不能看到其他代理商佣金。

## 七、升级与降级结构

代理商升级不是简单改角色，应走升级计划。

当前推荐升级路径：

```text
L0 普通用户
-> L1 推广员：注册申请
-> L2 初级代理商：累计销售 1000 元或缴纳 999 年费
-> L3 高级代理商：累计销售 1 万元或缴纳 2999 年费
-> L4 城市合伙人：合同签约 + 月销售 5 万目标
-> L5 联合运营商：战略合作合同
```

### 升级订单与普通会员订单的区别

代理商升级订单购买的是“渠道身份”，不是客户会员权益。

因此要区分：

- 客户会员套餐：影响用户能用哪些 AI 能力。
- 代理商升级套餐：影响用户能不能卖、能拿多少佣金、能看哪些渠道数据。

两者可以绑定销售策略，但数据库和业务状态不要混为一谈。

### 降级规则

建议支持人工降级和自动保级检查：

- L1 无保级要求。
- L2 月销售低于 1000，可提醒或降为 L1。
- L3 月销售低于 5000，可降为 L2。
- L4 季度销售低于 10 万，进入人工复核。
- L5 按合同处理。

降级不影响历史佣金，但影响新订单的返佣比例和权限。

## 八、风控边界

代理商体系至少要控制这些风险：

| 风险 | 控制方式 |
| --- | --- |
| 自买返佣 | 同一实名、手机号、支付账户、设备指纹订单不返佣或需审核 |
| 恶意退款 | 佣金设置冷静期，退款撤回佣金 |
| 跨渠道抢客户 | 客户归属快照 + 归属变更审计 |
| 价格混乱 | L1/L2 使用平台统一价，高级代理折扣需审核 |
| 多级分销风险 | 限制层级，佣金最多两层 |
| 数据越权 | 代理端接口只按当前代理可见范围返回数据 |
| 虚假业绩 | 只统计已支付、未退款、过冷静期订单 |

## 九、第一版建议落地

第一版建议先落地最稳的闭环：

1. L0-L5 等级展示和升级规则。
2. `channel_agents` 支持创建、启停、设置上级和邀请码。
3. 邀请码注册绑定客户归属。
4. 会员套餐和点数包订单支付后生成佣金。
5. 佣金支持审核、撤回、提现和结算单。
6. 代理端只能看自己的客户、订单、用量、佣金、提现。
7. 平台端能看代理树、等级、规则、钱包、结算。

暂缓：

- L5 独立 SaaS 站点。
- 独立支付账户。
- 复杂区域保护。
- 自动多层团队返佣。
- 代理商自定义商品价格。

## 十、推荐最终模型

推荐把代理商结构定义为：

```text
账号身份：users.role = AGENT_L1...AGENT_L5
渠道身份：channel_agents 记录邀请码、上级、状态
等级政策：marketing_roles / agentLevelPolicies 定义能力和限制
升级路径：marketing_upgrade_plans 定义开通和保级
客户归属：客户档案或推荐关系记录当前归属
交易事实：orders 保存商品、价格、权益和归属快照
佣金事实：commissions 保存金额、比例、规则快照和状态
结算事实：withdrawal_requests + settlement_statements
```

这样既能支撑当前轻量推广，也能逐步升级到城市合伙人和联合运营商，但不会一开始就把系统做成难以管控的复杂多级分销。
