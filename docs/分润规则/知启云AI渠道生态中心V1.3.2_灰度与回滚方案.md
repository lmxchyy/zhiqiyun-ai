# 知启云AI渠道生态中心 V1.3.2 灰度与回滚方案

## 1. 当前阶段边界

- 当前真实履约始终使用 legacy 结果。
- V1.3.2 只执行 shadow 计算并写独立差异记录。
- 灰度判定器和配置表已设计，但尚未接入真实佣金、Token、钱包、身份或平台收入写入。
- `applyCommerceOrderFulfillmentForTx` 保持唯一履约入口。

## 2. Shadow 规则固定

- 每个租户通过 `xz_channel_rollout_configs` 绑定唯一的 `pinned_rule_set_id + pinned_rule_set_version`。
- shadow 不再扫描或选择最新 DRAFT。
- 绑定规则的套餐金额、Token 权益、分润金额、关系层级和推荐奖励禁止原地修改。
- 调整规则必须创建新版本，完成模拟与 shadow 验证后再重新绑定。
- 规则状态从 DRAFT 发布为 PUBLISHED，以及对应佣金规则从 DRAFT 激活为 ACTIVE，不改变规则商业值，因此允许执行。

## 3. 灰度模式

| 模式 | Shadow计算 | 真实结算 | 用途 |
|---|---|---|---|
| LEGACY | 否 | Legacy | 紧急关闭全部 V1.3.2 旁路 |
| SHADOW | 是 | Legacy | 当前阶段 |
| V132_CANARY | 是 | 稳定哈希命中的订单使用 V1.3.2 | 下一阶段小比例灰度 |
| V132_FULL | 是 | V1.3.2 | 全量切换阶段 |

灰度比例使用基点配置，`100 = 1%`。命中依据为 `hash_salt + tenant_id + order_id` 的稳定哈希，同一订单重试不会漂移。拒绝名单优先于允许名单。

## 4. 小比例切换前置门槛

1. 固定规则版本连续运行 shadow，不允许中途修改。
2. 订单金额守恒差异必须为零。
3. 除明确取消的上级代理收益外，直属代理、运营中心和 Token 差异必须为零。
4. `ERROR` 比例达到约定阈值前不得进入灰度。
5. 退款、重复回调和履约幂等回放完成测试。
6. 测试数据库完成 `079-085` 迁移，生产数据库迁移单独审批。
7. 启用真实灰度必须同时设置 `mode=V132_CANARY` 与 `real_switch_enabled=true`。

## 5. 建议灰度节奏

1. 允许名单订单验证，不设置随机比例。
2. 1% 灰度，至少观察一个完整冻结周期。
3. 5% 灰度。
4. 20% 灰度。
5. 50% 灰度。
6. 100% 切换。

每一级只调整 rollout 配置，不修改规则版本。每次调整都会自动增加 `config_version` 并把旧配置写入历史表。

## 6. 回滚方案

### 6.1 灰度判定回滚

- 将 `mode` 改为 `SHADOW`。
- 将 `real_switch_enabled` 改为 `false`。
- 将 `canary_basis_points` 改为 `0`。
- 保留固定规则和 shadow 计算，用于继续诊断。

### 6.2 完全关闭 V1.3.2 旁路

- 将 `mode` 改为 `LEGACY`，或将 `enabled` 改为 `false`。
- legacy 履约继续工作。
- 已生成差异记录保持只读，不删除、不修正。

### 6.3 已产生真实 V1.3.2 订单后的回滚原则

- 已完成订单继续使用其订单规则快照，禁止改用 legacy 重算。
- 未履约新订单按回滚后的 rollout 配置执行。
- 已产生错误收益必须走负向流水冲正，不直接修改钱包余额或佣金记录。
- 回滚不删除规则版本、订单快照、差异记录和 rollout 历史。

## 7. 当前未实现内容

- 灰度判定结果尚未接入真实履约分支。
- 未提供 rollout 配置修改 API。
- 未提供后台灰度操作页面。
- 未切换真实佣金、Token、钱包、身份与退款链路。
